# Sequential graphics production

Read this procedure for motion graphics, continuation or saved Storyboard revisions. The managing agent selects assignments; the host performs delegation. The CLI saves project state and renders one occurrence at a time.

1. Read the original scenario and selected visual reference at work start. Retain an explicit decision to use a proposed style without an external reference. Preserve original narration, chapter context and purpose. Give each noncontiguous passage its own occurrence; retain the full plan without a chapter clip cap.
2. Select one occurrence. Record displayed facts, local materials, use conditions and narration timing. Missing sources, factual disputes and uncertain matches become questions on this occurrence; save its waiting checkpoint, then continue another assignment.
3. Save `graphics-handoff --occurrence ID --project PROJECT`. Give its packet and project access to one authorized scene specialist in a separate host context. Record `--host-context` only for an actual context. If delegation is unavailable or the editor requests solo work, use the packet yourself and report the limitation. A label or packet is not proof of host execution.
4. The specialist researches displayed facts, authors the visual and selects permitted effects. Use numeric, timeline or map templates for concrete reuse. For custom authoring, save one reviewed local JSX entry exporting `AuthorScene`, its permission declaration and editable content through `graphics-content`. Read [the graphics guide](../docs/GUIDE.md#graphics) for fields and limits. Return new scene ideas to the manager as separate proposals.
5. Save actual research/authoring files through `graphics-checkpoint`; render one occurrence and verify its declared output. After a scene-code failure, retain diagnostics and partial files and allow at most two repair-and-render attempts with unchanged narrative meaning. Keep the consumed count after interruption or code rebinding. Exhaustion leaves this occurrence unresolved and permits the next assignment.
6. Save each result before advancing. Produce previews without waiting for approval after every draft. Present Storyboard with the bounded VO interval and effects; collect exact-version human decisions separately. Rendering is neither editorial approval nor final delivery eligibility.
7. Process saved revisions only after explicit chat instruction. Save a handoff with `--request ID`, retaining the actually reviewed version and local scope. Explicitly select an older reviewed version before restoring its request. Complete the request with its new descendant version and actual outcome. Shared scope requires an explicit shared request. Replayed or stale requests are reported, never silently retargeted.
8. On context loss, read the latest intact packet, current status, checkpoint hashes, saved versions and sources. Reconstruct changed inputs from current state while retaining the old packet. Continue verified outputs; preserve repair counts and reuse unchanged narration analysis. Only the host can resume a specialist context.
9. Deliver an approved, current and permitted version with placement information and editable permitted sources. Report actual host delegation separately from tests, and retain factual, style, listening, live STT and Resolve gates.
