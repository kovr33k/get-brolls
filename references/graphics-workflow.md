# Sequential graphics production

Read this procedure for motion graphics, continuation or saved Storyboard revisions. Produce assignments sequentially in the managing context, saving each result before advancing. Subagents and host delegation are not required for the current workflow. The CLI saves project state and renders one occurrence at a time; retained handoff/context records remain compatible historical evidence.

1. Read the original scenario and selected visual reference at work start. Retain an explicit decision to use a proposed style without an external reference. Preserve original narration, chapter context and purpose. Give each noncontiguous passage its own occurrence; retain the full plan without a chapter clip cap.
2. Select one occurrence. Preserve the editor's factual choices and record local materials, use conditions and narration timing. Source catalogs can provide related statistics when needed; they do not authorize an independent full-script fact audit. Missing sources, recorded factual disputes and uncertain matches remain questions on the affected occurrence; save its waiting checkpoint, then continue another assignment. Editorial approval never silently resolves a separate factual or timing question.
3. When a recovery packet is useful, save `graphics-handoff --occurrence ID --project PROJECT` and use its immutable context yourself. It never launches an agent. Keep existing `--host-context` labels as historical records; do not invent a context or require delegation to proceed.
4. Author the visual from the recorded content and evidence and select permitted effects. Use numeric, timeline or map templates for concrete reuse. For custom authoring, save one reviewed local JSX entry exporting `AuthorScene`, its permission declaration and editable content through `graphics-content`. Read [the graphics guide](../docs/GUIDE.md#graphics) for fields and limits. Retain additional scene ideas as separate proposals instead of silently expanding the assignment.
5. Save actual research/authoring files through `graphics-checkpoint`; render one occurrence and verify its declared output. After a scene-code failure, retain diagnostics and partial files and allow at most two repair-and-render attempts with unchanged narrative meaning. Keep the consumed count after interruption or code rebinding. Exhaustion leaves this occurrence unresolved and permits the next assignment.
6. Save each result before advancing. Produce previews without waiting for approval after every draft. Present Storyboard with the bounded VO interval and effects; collect exact-version human decisions separately. Rendering is neither editorial approval nor final delivery eligibility.
7. Process saved revisions only after explicit chat instruction. Save a handoff with `--request ID`, retaining the actually reviewed version and local scope. Explicitly select an older reviewed version before restoring its request. Complete the request with its new descendant version and actual outcome. Shared scope requires an explicit shared request. Replayed or stale requests are reported, never silently retargeted.
8. On context loss, read the latest intact packet, current status, checkpoint hashes, saved versions and sources. Reconstruct changed inputs in the managing context while retaining the old packet. Continue verified outputs; preserve repair counts and reuse unchanged narration analysis.
9. Deliver an approved, current and permitted version with placement information and editable permitted sources. Record human acceptance for the actual unchanged files separately from technical tests. When the agreed test stops at the supplied narration, retain other concepts as estimated visual drafts rather than fabricating VO or declaring them montage-ready.
