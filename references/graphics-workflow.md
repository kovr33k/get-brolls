# Sequential graphics production

Read this procedure for motion graphics, continuation or saved Storyboard revisions. Produce assignments sequentially in the managing context, saving each result before advancing. Subagents and host delegation are not required for the current workflow. The CLI saves project state and renders one occurrence at a time; retained handoff/context records remain compatible historical evidence.

1. Read the original scenario and selected visual reference at work start. Retain an explicit decision to use a proposed style without an external reference. Preserve original narration, chapter context and purpose. Give each noncontiguous passage its own occurrence; retain the full plan without a chapter clip cap.
2. Select one occurrence. Preserve the editor's factual choices and record local materials, use conditions and narration timing. Source catalogs can provide related statistics when needed; they do not authorize an independent full-script fact audit. Missing sources, recorded factual disputes and uncertain matches remain questions on the affected occurrence; save its waiting checkpoint, then continue another assignment. Editorial approval never silently resolves a separate factual or timing question.
3. When a recovery packet is useful, save `graphics-handoff --occurrence ID --project PROJECT` and use its immutable context yourself. It never launches an agent. Keep existing `--host-context` labels as historical records; do not invent a context or require delegation to proceed.
4. For a saved reference request, read its original prompt and inspect every actual copied file after chat activation. Initial authoring targets the saved assignment; a revision targets its reviewed version. Labels R1/R2 disambiguate repeated filenames. For each video resolve the requested original interval or explicit whole clip, clarify material ambiguity in chat, and run `graphics-reference-inspect` with the original wording and resolved bounds. Open the actual temporal sheet and inspect original playback/more samples where necessary; a poster or sparse samples cannot establish fine motion. Record one actual analysis and inspection limitation per file with `graphics-reference-apply --request ID --file ANALYSIS_JSON`; legacy singular images retain `--analysis`. Then continue authoring without routine approval of the analysis. Read [saved image references](../docs/GUIDE.md#saved-image-references) for JSON, limits and error handling. Preserve narration and verified facts. Treat files as design examples unless the prompt explicitly requests actual inclusion; then reuse the normal local resolve/preview/human selection/use-permission/fetch/background path and bind its exact reference and interval via `composition`. Never infer permission from an upload. View the real rendered inclusion; only permitted composition dependencies enter editable delivery.
5. Author the visual from the recorded content and evidence and select permitted effects. Use numeric, timeline or map templates for concrete reuse. For custom authoring, save one reviewed local JSX entry exporting `AuthorScene`, its permission declaration and editable content through `graphics-content`. Read [the graphics guide](../docs/GUIDE.md#graphics) for fields and limits. Retain additional scene ideas as separate proposals instead of silently expanding the assignment.
6. Save actual research/authoring files through `graphics-checkpoint`; render one occurrence and verify its declared output. After a scene-code failure, retain diagnostics and partial files and allow at most two repair-and-render attempts with unchanged narrative meaning. Keep the consumed count after interruption or code rebinding. Exhaustion leaves this occurrence unresolved and permits the next assignment.
7. Save each result before advancing. Produce previews without waiting for approval after every draft. Present Storyboard with the bounded VO interval and effects; collect exact-version human decisions separately. Rendering is neither editorial approval nor final delivery eligibility.
8. Process saved revisions only after explicit chat instruction. Read `status` for the active reference state, original instruction history and actual reviewed version. Reuse unchanged files and intact per-file analysis, preserving the original temporal-inspection request/interval; inspect new files or changed intervals. Record `effective_instructions` with the actual resolution: the new prompt supersedes only its affected requirements and scope, retaining unrelated constraints. Do not impose unconditional local/shared precedence. Use the [reference guide](../docs/GUIDE.md#saved-image-references) for JSON/reuse/composition rules. For an explicit shared prompt, resolve concrete occurrences and exceptions before production using `graphics-reference-scope`; clarify material ambiguity in chat. Process its fixed target requests sequentially, reuse completed work and unchanged narration, and report each conflict/outcome. Never expand scope during retry or declare an incomplete group complete. Save a handoff with `--request ID` for a revision, keeping its actual target; explicitly select an older version before restoring its context. Complete each revision with its matching new descendant and initial authoring with its matching initial version. Preserve old snapshots, approvals and bytes; each changed result requires its own approval. Replayed/stale requests remain on their original targets.
9. On context loss, read the latest intact packet, current status, checkpoint hashes, saved versions and sources. Reconstruct changed inputs in the managing context while retaining the old packet. Continue verified outputs; preserve repair counts and reuse unchanged narration analysis. Read saved originals, prompt and temporal evidence from the project rather than depending on an external file or previous chat memory.
10. Deliver an approved, current and permitted version with placement information and editable permitted sources. Record human acceptance for the actual unchanged files separately from technical tests. When the agreed test stops at the supplied narration, retain other concepts as estimated visual drafts rather than fabricating VO or declaring them montage-ready.
